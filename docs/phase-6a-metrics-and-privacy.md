## 1. 评估目标

阶段 6 后续工作需要回答以下问题：

1. 用户是否能快速完成推荐流程：快速推荐是否能在 30 秒内完成，精准筛选是否能在不过度犹豫的情况下完成。
2. 推荐是否容易理解：用户能否说出推荐菜品、至少一条真实理由，以及这是“菜品灵感”而不是真实外卖结果。
3. 用户是否需要返工：用户是否返回修改条件、重新筛选、选择替代项或连续点击“换一个”。
4. 推荐是否推动了下一步：用户是否复制菜名。复制只表示准备继续搜索，不能解释为接受推荐或完成下单。
5. 多人模式是否帮助决策：多人是否能理解当前人数输入的作用、达成共同选择，以及现有简化模式是否缺少逐人偏好。当前实现只能先通过人工任务评估，不能仅靠事件证明多人决策质量。
6. 菜品灵感模式是否减少选择困难：用户是否能在较短时间内从“没有方向”变为“有一个愿意继续搜索的菜品方向”，并能准确理解产品能力边界。
7. 错误与空结果是否可恢复：用户是否知道发生了什么、下一步可以做什么，以及是否能通过调整条件或重试恢复。

### 可解释的核心指标

| 指标 | 计算口径 | 可以说明 | 不能说明 |
| --- | --- | --- | --- |
| 流程完成率 | 完成推荐的会话数 / 开始推荐的会话数 | 用户能否走到结果 | 推荐是否正确、是否下单 |
| 完成时长 | 从开始到显示结果的时长分桶及中位数 | 流程是否足够快 | 配送速度、用户最终决策时间 |
| 重新筛选率 | 完成后修改条件的会话数 / 已完成会话数 | 初始输入或结果可能不够合适 | 具体不满意原因 |
| 更换推荐率 | 至少更换一次的会话数 / 已完成会话数 | 首选可能未直接解决选择 | 更换后的菜是否被下单 |
| 连续更换分布 | 每个会话的更换次数分桶 | 选择困难是否仍然存在 | 用户情绪或真实购买意图 |
| 复制率 | 复制菜名的会话数 / 已完成会话数 | 用户愿意继续去平台搜索 | 真实接受率、订单转化率 |
| 错误展示率 | 显示错误的会话数 / 开始推荐的会话数 | 流程可靠性线索 | 外卖 Provider 可靠性 |

### 当前不能测量的指标

在阶段 4 完成前，以下指标没有合法事实基础，不得计算或推断：

- 真实价格、配送费、订单总价及预算命中率；
- 真实距离、ETA、准时率或配送体验；
- 商家营业、菜品库存、可售状态和数据新鲜度；
- 真实平台跳转、加购、支付、订单或复购转化；
- 商家质量、销量、评分对选择的影响；
- 实时 Provider 的成功率、延迟、降级率和数据覆盖率。

## 2. 当前产品边界

- 当前生产界面只使用仓库内 175 条静态菜品作为灵感。
- 当前没有真实商家、实时价格、配送费、距离、ETA、库存或营业状态。
- 当前主操作主要是复制菜名，供用户自行前往平台搜索，不是真实订单深链。
- 当前不请求精确位置；`PROVIDER_CONFIG.endpoint` 和实际 `liveProvider` 均未启用。
- 当前多人输入是简化人数信息，不包含逐人偏好与结果归属，不能把它描述为完整多人决策模式。
- 当前没有账号、跨设备身份或已批准的遥测接收端。
- 静态灵感的点击、复制或更换行为不得解释为真实外卖接受率、订单转化率、履约质量或商业表现。
- 阶段 6 不能替代阶段 4。只有合法数据来源、公开前端 endpoint、服务端安全边界和契约验收全部通过后，才能启用实时外卖模式。

## 3. 最小事件集设计

本节只定义候选事件。阶段 6A 不发送这些事件。

### 共享字段

若未来遥测获得批准，所有事件最多使用以下共享字段：

| 字段 | 规则 |
| --- | --- |
| `event_name` | 本文批准的固定枚举 |
| `schema_version` | 固定版本号；不兼容变更升 major |
| `occurred_at` | UTC 时间，服务端仅保留评估所需精度，不用于构建设备轨迹 |
| `session_id` | 客户端随机生成的短期标识，最长 24 小时失效；不得复用为永久用户 ID |
| `flow_type` | `quick` 或 `precise` |
| `source_mode` | 当前只能是 `inspiration`；未来 `live` 必须来自真实 Provider 响应 |
| `viewport_class` | `small`、`medium`、`large`，不得上传精确屏幕指纹组合 |
| `app_version` | 公开发布版本或提交短 SHA |

不得加入设备广告标识、浏览器指纹、跨站 ID、精确网络地址或用于重识别的字段组合。IP 地址如因网络服务不可避免地短暂经过基础设施，不得写入分析数据集，并须在接收端设计与法律审查中单独确认。

### 事件定义

| 事件 | 触发时机 | 必要事件字段 | 禁止字段 | 用途 | 未来最小遥测是否必需 |
| --- | --- | --- | --- | --- | --- |
| `recommendation_started` | 用户点击“马上推荐”或在精准流程确认后点击生成推荐 | 共享字段、`entry_point`、`party_size_bucket` | 口味原值、忌口原文、菜名、精确人数大值、位置 | 计算流程启动量和完成漏斗 | 是 |
| `recommendation_completed` | 成功显示一个主推荐时，每次请求最多一次 | 共享字段、`duration_bucket`、`result_count_bucket`、`has_tradeoff` | 菜名、候选 ID、评分明细、价格/距离/ETA 占位值 | 计算完成率、时长和结果可用性 | 是 |
| `recommendation_refined` | 用户在已有输入或结果后返回并修改筛选条件 | 共享字段、`changed_dimension`、`from_result` | 修改前后具体值、忌口原文、自由文本 | 判断哪些输入造成返工 | 否，首轮试点可暂缓 |
| `recommendation_replaced` | 用户点击“换一个”或选择替代候选 | 共享字段、`replacement_count_bucket`、`replacement_source` | 原/新菜名、候选 ID、自由文本原因 | 衡量首选是否减少选择困难 | 是 |
| `recommendation_copied` | 菜名成功写入剪贴板；失败不得记为成功 | 共享字段、`selection_source` | 菜名、剪贴板内容、平台信息 | 衡量继续搜索意向；不得称为下单 | 是 |
| `recommendation_reset` | 用户主动重置本次选择 | 共享字段、`from_state` | 重置前的偏好、忌口、历史和自由文本 | 判断流程放弃或重新开始的位置 | 否，首轮试点可暂缓 |
| `error_shown` | 用户界面实际展示可恢复或不可恢复错误 | 共享字段、允许列表中的 `error_code`、`surface`、`recoverable` | 原始异常、堆栈、请求/响应体、URL 参数、用户输入 | 发现影响完成流程的错误 | 是 |

字段枚举要求：

- `entry_point`：`quick`、`precise_confirmation`。
- `party_size_bucket`：`1`、`2`、`3_plus`；不记录更细人数。
- `duration_bucket`：`under_10s`、`10_to_30s`、`30_to_60s`、`over_60s`。
- `result_count_bucket`：`0`、`1`、`2_plus`。
- `changed_dimension`：`scene`、`taste`、`exclusion_presence`、`party_size`；只说明维度，不记录值。
- `replacement_count_bucket`：`1`、`2`、`3_plus`。
- `replacement_source`：`swap_button`、`alternative`。
- `selection_source`：`primary`、`alternative`。
- `from_state`：`input`、`result`、`empty`、`error`。
- `error_code` 必须是代码内批准的低基数枚举；未知错误统一为 `UNKNOWN_ERROR`，不得把错误消息作为字段。

### 全局禁止收集字段

无论使用哪个事件，默认禁止收集：

- 姓名、手机号、邮箱、账号信息或其他直接身份标识；
- 精确位置、经纬度、精确地址、定位精度或长期区域轨迹；
- IP 地址、设备广告标识、浏览器指纹或未经同意的跨站追踪信息；
- 聊天内容、剪贴板内容、菜名搜索历史或订单链接；
- 忌口、过敏原和其他原始自由文本；
- 完整 User-Agent、完整 URL、查询参数、Referer 或网络响应体；
- 可直接或通过组合字段合理识别个人的信息。

## 4. 匿名化与隐私原则

1. 当前优先使用人工可用性测试、离线固定样本和现有自动化测试；遥测不是阶段 6A 的默认下一步。
2. 未来如启用遥测，默认关闭并采用明确的用户选择机制；具体同意方式和适用法律要求标记为“待人工确认”。
3. 只允许短期随机 `session_id`，最长 24 小时轮换；不创建永久用户标识，也不把本地偏好键当作身份。
4. 不收集精确地理位置，不从 IP 推断或保存精确位置。
5. 不记录原始自由文本。若未来证明某类文本确有必要，必须先完成单独的数据保护评审、替代方案比较和明确同意设计。
6. 数据最小化优先：每个字段必须能对应本文的一个评估问题；没有决策用途的字段不得加入。
7. 事件在客户端与接收端都必须使用固定 schema 和低基数枚举，禁止任意扩展属性袋。
8. 分析结果只用于人工评估和可复现的版本迭代，不进行在线自学习、个体画像或自动化差别待遇。
9. 启用前必须明确数据接收端、处理地区、子处理方、访问权限、泄露响应和审计方式。
10. 本文不是法律意见。个人信息保护法、网络安全、跨境传输、未成年人、Cookie/同意和第三方处理要求均为“待人工确认”，不得声称已经合规。

## 5. 数据保留与退出机制

### 保守初始建议

如果未来遥测试点获得批准，**原始事件最多保留 30 天是默认方案**。30 天不是当前授权：在遥测实现、接收端和隐私方案另行批准前，生产环境仍然不收集事件。

**去标识聚合结果最多保留 90 天不是默认方案，必须额外批准。** 额外批准前需要说明保留聚合结果将支持哪个产品决策、聚合是否达到最小样本阈值、由谁访问，以及如何按期删除；没有批准时，聚合结果应与 30 天原始事件一起删除。

| 项目 | 初始建议 |
| --- | --- |
| 原始事件保留 | 默认最多 30 天，到期自动删除 |
| 去标识聚合结果 | 可选最多 90 天；只保留达到最小样本阈值且另行获批的汇总 |
| 会话标识有效期 | 最长 24 小时，不跨设备、不长期续期 |
| 最小汇总样本 | 少于 10 个会话不单独展示或导出分组结果 |
| 访问人员 | 仓库所有者和最多 2 名明确指定的产品/工程维护者 |
| 导出 | 默认禁止含原始事件的个人设备下载；必要导出须记录目的和删除日期 |

### 删除与退出

- 产品必须提供与数据说明同级、易发现的退出入口；退出后不得继续发送事件。
- 用户选择退出时，应立即停止新收集，并清除本地短期会话标识和待发送队列。
- 未登录且不使用永久标识时，可能无法定位并删除已经去标识的单个历史事件；这一限制必须在启用前向用户说明，并由人工确认其法律充分性。
- 接收端必须支持按日期批量删除、删除测试数据和停止全部写入。
- 停止收集应由一个可独立关闭的配置开关控制；关闭后客户端不得初始化 SDK、创建会话标识或发出网络请求。
- 出现误收敏感字段、未经批准的 schema 变化、接收端权限异常或疑似泄露时，应立即关闭遥测、冻结访问、保留必要审计证据，并按人工确认的事件响应流程处理。
- 数据接收端、删除责任人、备份删除方式、监管或用户请求流程均为“待人工确认”。在这些事项落实前不得启用生产遥测。

## 6. 离线评估方案

### 固定测试样本

建立版本化测试矩阵，至少覆盖 24 个固定样本：

- 快速与精准两种入口；
- `balanced`、`comfort`、`lighter`、`novelty` 四种当前状态；
- 无口味、单口味、三口味和冲突偏好；
- 无忌口、单一忌口、多项忌口、会清空候选的忌口；
- 1 人、2 人、3 人及以上的人数桶；
- 空历史、重复历史和接近历史上限；
- 正常输入、空结果、超长/异常分隔的自由文本；
- 固定时间和固定候选集合下的重复运行。

每个样本记录输入、候选集合版本、预期过滤、预期首选或空结果、预期理由代码、禁止出现的声明和实际结果。样本不得包含真实个人信息。

### 自动化通过标准

| 检查 | 通过标准 |
| --- | --- |
| 推荐稳定性 | 同一输入、候选和时间重复运行 20 次，结果深度相等 |
| 过滤正确性 | 已知忌口、过敏原和不合法候选违规为 0 |
| 灵感真实性 | 商家、实时价格、距离、ETA、营业、库存和真实下单声明出现次数为 0 |
| 人数逻辑 | 1、2、3+ 桶均不崩溃；界面不暗示当前已实现逐人偏好 |
| 推荐解释 | 每个成功结果至少有一条能由字段或评分贡献验证的理由；不得把未知条件写成满足 |
| 空结果 | 明确说明没有合适结果，并提供可恢复操作；不得建议放宽忌口 |
| 异常输入 | 超长、空白、重复和异常分隔输入被安全规范化或拒绝，不进入日志 |
| 回归 | `npm test`、构建检查及现有 Chromium E2E 全部通过 |

### 人工可用性测试

首轮建议至少招募 5 名真实测试者，避免全部来自项目开发者。每人完成：

1. 不看说明使用“马上推荐”，找到一个愿意继续搜索的菜品方向。
2. 使用精准筛选表达口味和忌口，并解释结果为什么出现。
3. 对首选不满意时换一个或选择替代项。
4. 复制菜名，并说明复制之后还需要去哪里确认什么信息。
5. 以 2 人或 3 人场景尝试共同决定，并指出当前多人能力是否足够。
6. 遇到预设的空结果或错误状态后尝试恢复。

人工测试通过门槛：

- 至少 4/5 测试者在无协助下完成快速推荐，且用时不超过 30 秒；
- 至少 4/5 能正确说出一条推荐理由；
- 5/5 能明确说出当前结果不是实时商家、价格、配送或库存信息；
- 至少 4/5 能完成更换推荐和复制菜名；
- 至少 4/5 能从空结果或错误状态找到恢复动作；
- 多人任务不设虚假的转化门槛，而是记录是否需要逐人偏好、结果归属或共同确认；
- 不出现阻断任务的严重可用性问题；若出现，修复并重测后才能通过。

### 人工测试记录表

| 字段 | 记录规则 |
| --- | --- |
| 测试编号 | 使用 `P01` 等临时代号，不记录姓名或联系方式 |
| 设备与视口 | 只记设备类别和宽度档，不记设备唯一标识 |
| 任务 | 固定任务编号 |
| 是否完成 | 是 / 否 / 需协助 |
| 用时 | 秒；仅记录任务用时 |
| 理解检查 | 是否理解推荐理由与灵感模式边界 |
| 操作路径 | 预定义动作枚举，不记录屏幕录像中的个人信息 |
| 困惑点 | 研究员归纳，不逐字保存可能含个人信息的原话 |
| 严重度 | 阻断 / 严重 / 一般 / 建议 |
| 后续决策 | 保持、修改、补充测试或暂不处理，并写明理由 |

测试者招募、知情说明、录音录像、补偿和原始研究材料保留要求均为“待人工确认”。默认不录音、不录像。

## 7. 阶段 6A 暂缓事项

当前禁止直接实施：

- 添加 analytics SDK 或自行实现 analytics 发送模块；
- 添加第三方追踪脚本、像素、Cookie 或跨站标识；
- 创建数据库、数据仓库、日志管道或数据接收服务；
- 上传、转发或导出真实用户行为数据；
- 接入真实外卖 Provider、平台私密 API 或生产 endpoint；
- 修改推荐权重、算法、UI 行为或存储规则来配合尚未批准的指标；
- 把菜名复制率、替代项点击率或静态灵感偏好解释为真实订单转化率；
- 为了“看起来有数据”收集菜名、忌口原文、精确人数、完整 URL、设备指纹或其他非必要信息；
- 在未明确接收端、权限、保留、删除、退出和法律要求前启用生产遥测。

## 8. 后续决策门

只有以下条件全部满足，才能提出阶段 6B 遥测实现方案：

1. 人工与离线评估已执行，并证明仍有必须依靠聚合遥测回答的问题。
2. 每个拟收集事件和字段都有明确产品决策用途，且无法由更少数据替代。
3. 数据接收端、处理地区、访问人、保留和删除机制已确定。
4. 用户告知、同意或其他合法基础、退出方式及适用法律要求已经人工确认。
5. 有独立配置可以默认关闭并紧急停用全部收集。
6. 有 schema 契约测试，能证明禁止字段不会进入请求。
7. 新方案通过独立 Pull Request 审查；不得与阶段 4 Provider 接入或推荐算法调整混在同一变更中。

阶段 4 仍保持独立且未完成。阶段 6A 设计通过后，生产状态仍应明确标注：只提供菜品灵感，analytics 代码尚未实施，没有遥测数据。
