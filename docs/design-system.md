# Meal-Serendipity 设计系统

状态：极简智能型方向已确认。本文是后续页面和组件实现的唯一视觉基线。

## 设计命题

页面的单一工作是让用户尽快做出一个可信的外卖决定。界面应像清晰、友好的决策助手，而不是品牌海报、外卖平台信息流或聊天机器人。

## 明确停止使用

- 宣纸、朱砂、墨色、黛青、描金作为主视觉体系；
- 楷体、竖排章节、印章、卷轴、月洞门和古风题签；
- “落笔定案、择此一席、门庭、天时”等妨碍快速理解的文案；
- 为仪式感增加的独立模式页、长等待和摇签动画；
- 大面积深色推荐卡、低对比备选卡和装饰性进度章。

可保留“一餐之缘”名称，但界面默认使用 Meal-Serendipity 或“一餐之缘”现代字标，不延续古风造型。

## 视觉方向：极简智能型

### 关键词

清楚、快速、可信、轻松、克制、有食欲但不过度娱乐化。

### 标志性元素：决策跑道

主推荐卡顶部使用一条紧凑的“决策跑道”，展示预算、ETA、距离、口味四个关键条件：

```text
预算内 ✓  ──  28–35 分钟 ✓  ──  1.2km ✓  ──  香辣匹配 ✓
```

它不是装饰，而是用户理解推荐依据的最快入口。其余视觉保持安静，避免与跑道和主 CTA 竞争。

## 设计原则

1. 首屏先完成任务，再解释产品。
2. 默认给一个答案，替代项明确标注“更快、更便宜、更新鲜”。
3. 结构表达真实信息；不用无意义编号、图章或装饰分隔。
4. 价格、预计送达、距离和硬约束状态始终优先于描述文案。
5. 状态不能只靠颜色表达，必须同时有文字或图标。
6. 移动端从 320px 开始设计，桌面端采用真正的双栏决策布局。
7. 动效只用于状态反馈和候选切换；支持减少动效。
8. 文案使用用户能直接理解的现代口语和主动语态。

| `--color-surface` | `#FFFFFF` | 卡片、输入区域、弹层 |
| `--color-text` | `#16181D` | 主文字 |
| `--color-muted` | `#667085` | 次级说明 |
| `--color-border` | `#E3E7EE` | 边框与分隔 |
| `--color-primary` | `#315EFB` | 主操作、选中状态 |

| `--color-food` | `#FF6B35` | 食物、价格和少量情绪强调 |

### 使用规则

- 主操作只使用 `--color-primary`，页面不同时出现多个高饱和主按钮。
- `--color-food` 只强调菜品和价格，不作为第二套主操作色。
- 成功、警告、错误必须同时显示文字或图标。
- 正文和关键数据需达到 WCAG 2.2 AA 对比度；禁用文字仍须可辨认。

## 字体 Token

首个版本不下载中文 Web Font，使用系统字体降低加载成本并避免许可与子集问题。

```css
--font-body: system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif;
--font-data: "DIN Alternate", "Inter", "SF Pro Display", system-ui, sans-serif;
```

| Token | 字号/行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| `--text-display` | `36/44px` | 750 | 桌面主标题 |
| `--text-display-mobile` | `28/34px` | 750 | 移动主标题 |
| `--text-title` | `22/30px` | 700 | 推荐名称、区块标题 |
| `--text-subtitle` | `18/26px` | 650 | 卡片标题 |
| `--text-body` | `16/24px` | 400 | 正文和输入 |
| `--text-label` | `14/20px` | 600 | 标签和按钮 |
| `--text-caption` | `12/18px` | 500 | 时间戳和辅助信息 |

价格、距离、ETA 使用 `--font-data` 并启用 `font-variant-numeric: tabular-nums`。正文不得小于 14px；12px 仅用于非关键辅助信息。

## 布局

### 移动端

```text
┌──────────────────────┐
│ Logo          历史   │
│ 30 秒选好这顿外卖    │
│ 位置                 │
│ 预算  ·  最晚送达    │
│ 当前更在意什么       │
│ [更多偏好]           │
│                      │
│ [给我一个推荐]       │ ← 底部可达
└──────────────────────┘
```

- 关键条件在首屏完成；更多偏好使用折叠区或底部抽屉。
- 主操作在长内容中可使用安全区感知的底部操作栏。
- 推荐首屏应完整显示候选名称、总价、ETA、距离、两条理由和“去下单”。

### 桌面端

```text
┌────────────────────────────────────────────────────┐
│ Logo                                  历史 / 偏好 │
├────────────────────┬───────────────────────────────┤
│ 决策条件 360–420px │ 主推荐                         │
│ 位置、预算、ETA    │ 决策跑道                       │
│ 状态、口味、忌口   │ 理由、取舍、去下单             │
│                    │ 替代候选                       │
└────────────────────┴───────────────────────────────┘
```

- 最大内容宽度 1180px；右侧推荐区占剩余空间。
- 不把移动端长表单原样居中放大。

### 响应式断点

| 范围 | 行为 |
| --- | --- |
| `0–479px` | 紧凑单栏，16px 页面边距 |
| `480–767px` | 宽松单栏，20–24px 页面边距 |
| `768–1023px` | 两栏或主次区域切换 |
| `1024px+` | 360–420px 条件栏 + 自适应结果栏 |

必须在 320px、390px、768px 和 1440px 验证，不允许横向滚动。

## 组件

### 应用与输入

- `AppHeader`：字标、历史和偏好入口。
- `LocationControl`：定位、手动区域、权限失败和加载状态。
- `BudgetControl`：订单总预算，不使用模糊人均档位。
- `DeliveryTimeControl`：最大 ETA 和必要时的距离上限。
- `PrioritySelector`：快一点、便宜一点、吃得满足、清淡舒服、想吃点新的。
- `PreferenceDisclosure`：折叠口味、忌口和人数。
- `TasteChips` / `ExclusionPicker`：具备可访问的选中状态。
- `ContextSummary`：提交前用一句话汇总条件。

### 推荐与反馈

- `RecommendationCard`：唯一主推荐。
- `DecisionRunway`：预算、ETA、距离、口味状态。
- `ReasonList`：结构化原因，不展示算法内部权重。
- `TradeoffNotice`：明确软条件取舍。
- `AlternativeCard`：更快、更便宜、更新鲜。
- `EmptyResult`：解释无候选并建议只放宽一个软条件。
- `ModeNotice`：明确实时模式或灵感模式。
- `PlatformHandoff`：平台跳转、复制关键词和失败后备。
- `ToastRegion`：非关键短反馈，使用 `aria-live="polite"`。
- `Dialog`：权限、清除和重要确认，具备焦点锁定与恢复。

### 统一状态

所有交互组件必须定义：default、hover、focus-visible、pressed/selected、disabled、loading、error 和 unavailable。加载时保持控件尺寸稳定；错误信息靠近控件并说明恢复动作。

## 文案

- 主标题：`30 秒，选好这顿外卖`
- 主按钮：`给我一个推荐`
- 重新推荐：`换一个`
- 下单：`去下单`
- 折叠区：`更多偏好`
- 定位失败：`无法获取位置，请选择送达区域`
- 无候选：`暂时没有同时满足这些条件的选择`
- 灵感模式：`当前无法读取附近商家，先给你一个菜品方向`

避免“提交、落笔定案、择此一席、认命、违抗命运”等文案。标签负责命名，说明负责解释，按钮只描述点击后的动作。

## 动效

- 控件反馈 120–180ms；推荐切换不超过 300ms。
- 唯一编排动效是“比较候选 → 决策跑道依次确认 → 展示结果”，总时长不超过 600ms，数据已返回时不得人为等待。
- `prefers-reduced-motion: reduce` 下取消位移、缩放、晃动和依次出现，只保留必要的透明度变化。
- 加载超过 800ms 显示进度文案，超过 8 秒进入可恢复错误状态。

## 可访问性

- 使用 `<main>`、唯一 `<h1>`、顺序正确的标题和真实 `<form>`。
- 每个输入有可见 `<label>` 或等效可访问名称。
- 选择按钮使用 `aria-pressed`，当前步骤/页面使用 `aria-current`。
- 键盘焦点使用 3px `--color-focus` 环，不移除 outline 后只用颜色代替。
- 对话框使用 `role="dialog"`、`aria-modal="true"`，支持 Escape、焦点锁定和关闭后焦点恢复。
- 错误摘要与字段错误关联；重要状态使用 `aria-live`。
- 触控目标至少 44×44px；支持 200% 缩放和减少动效。
- 发布前以 WCAG 2.2 AA 为验收基线。

## 性能预算

- LCP ≤ 2.5s，CLS ≤ 0.1，INP ≤ 200ms。
- 首屏 JS gzip ≤ 80KB；首屏图片总量 ≤ 250KB。
- 首个版本不依赖食物摄影和外部中文字体。
- 图标优先使用小型 SVG sprite，不为每个控件内联重复的大段 SVG。

## 设计交付检查

- 提供 320px、390px、768px 和 1440px 截图。
- 覆盖默认、加载、无候选、定位拒绝、灵感模式、实时结果和平台跳转失败。
- 检查键盘顺序、焦点、对比度、200% 缩放和减少动效。
