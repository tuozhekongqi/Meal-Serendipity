# 设计系统基础

本文记录当前视觉语言与后续演进约束，不代表要求重做现有页面。

## 体验基调

- 关键词：现代、简洁、舒服、克制的中式仪式感。
- 装饰应帮助建立节奏与情绪，不能削弱信息层级、可读性或操作效率。
- 优先通过留白、字号、对比和结构建立层级，再使用印章、描金、纹样和动画。

## 字体与排版

- 正文使用系统中文无衬线栈，保证跨平台加载速度与清晰度。
- 标题、印章和仪式性短句可使用楷体回退栈；长正文和表单标签不使用书法字体。
- 正文默认行高约 1.6，数字使用等宽数字特性以稳定价格布局。
- 文案应短、具体、可行动；避免连续多段古风表达遮蔽真实含义。

## 布局与响应式

- 移动端优先，最低支持宽度为 320px。
- 当前内容容器最大宽度为 720px，封面主体最大宽度为 520px。
- 单列是默认结构；只有在空间足够且不会缩小触控目标时才扩展为多列。
- 页面必须避免横向滚动，长菜名、价格、标签和按钮文案应有明确换行或截断策略。

## 组件原则

- 主按钮：每个页面最多一个最强主操作，使用朱砂强调。
- 次按钮：卡片或描边样式，不与主操作争夺视觉注意力。
- 选择项：选中、未选、禁用和错误状态不能只依赖颜色区分。
- 方案卡：清楚区分首选、稳妥和尝鲜，并让推荐理由靠近对应菜品。
- 反馈：使用就近错误提示、明确空状态和短暂 toast；重要错误不能只依赖 toast。
- 下单链接：明确平台、菜名和即将离开当前页面的结果，并保留复制搜索词的后备路径。

## 动效

- 动效只表达进入、选择、结果揭晓和状态切换。
- 高频交互保持短促；摇签等仪式性动效可以更长，但必须可恢复且不能产生竞态。
- 为 `prefers-reduced-motion: reduce` 提供降级，避免强制位移、晃动和长时间等待。

## 可访问性检查

- 交互目标至少约 44×44px，键盘焦点清晰可见。
- 使用原生按钮、输入框和链接语义；图标应有合适的可访问名称或 `aria-hidden`。
- 表单标签与控件建立明确关联，错误消息可被读屏感知。
- 验证颜色对比、200% 缩放、键盘导航、减少动效和常见移动端视口。
