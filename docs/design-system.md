# Meal-Serendipity 设计系统

状态：阶段 3.7 的场景化中性编辑型界面已实现并通过本地验收。本文是后续页面和组件实现的唯一视觉基线。

## 设计命题

页面的单一工作是让用户尽快做出一个可信的外卖决定。界面应像清晰、友好的决策助手，而不是品牌海报、外卖平台信息流或聊天机器人。

## 明确停止使用

- 宣纸、朱砂、墨色、黛青、描金作为主视觉体系；
- 楷体、竖排章节、印章、卷轴、月洞门和古风题签；
- “落笔定案、择此一席、门庭、天时”等妨碍快速理解的文案；
- 为仪式感增加的独立模式页、长等待和摇签动画；
- 大面积深色推荐卡、低对比备选卡和装饰性进度章。

可保留“一餐之缘”名称，但界面默认使用 Meal-Serendipity 或“一餐之缘”现代字标，不延续古风造型。

## 视觉方向：中性编辑型

### 关键词

低饱和、安静、可信、克制、有人文温度。内容和排版优先于装饰，主题背景只提供轻微环境感。

### 标志性元素：决策跑道

主推荐区域顶部使用一组由细线分隔的“决策跑道”，展示预算、ETA、距离、口味四个关键条件：

```text
预算内 ✓  ──  28–35 分钟 ✓  ──  1.2km ✓  ──  香辣匹配 ✓
```

它是信息表格，不是彩色横幅或装饰卡。其余视觉通过排版、留白和细线建立层级。

## 设计原则

1. 首屏先完成任务，再解释产品。
2. 默认给一个答案；替代项只标注可验证差异。灵感候选只使用口味、品类或中性文案，实时候选仅在双方都有可比字段时使用“更快送达”或“更便宜”。
3. 结构表达真实信息；不用无意义编号、图章或装饰分隔。
4. 价格、预计送达、距离和硬约束状态始终优先于描述文案。
5. 状态不能只靠颜色表达，必须同时有文字或图标。
6. 移动端从 320px 开始设计，桌面端采用真正的双栏决策布局。
7. 动效只用于状态反馈和候选切换；支持减少动效。
8. 文案使用用户能直接理解的现代口语和主动语态。

## 颜色与背景主题

页面一次只启用一个主题。根节点使用唯一的 `data-theme`，当前默认值为 `quick`；主题由用户选择的场景决定，本阶段不提供公开切换按钮，也不保存主题偏好。

| 主题 | 页面背景 | 柔和背景 | 卡片 | 次级表面 |
| --- | --- | --- | --- | --- |
| Quick（默认；快速/省钱） | `#F3F4F3` | `#FAFBFA` | `#FFFFFF` | `#E9ECE9` |
| Focus（学习/工作） | `#EEF3F6` | `#F8FAFC` | `#FFFFFF` | `#E3EBF0` |
| Lighter（清淡） | `#EEF7F1` | `#F8FCF9` | `#FFFFFF` | `#E1EFE5` |
| Gathering（多人） | `#FBF4E2` | `#FFFCF5` | `#FFFFFF` | `#F3E9CF` |
| Celebration（想吃点好的/庆祝） | `#F4EFF8` | `#FCFAFD` | `#FFFFFF` | `#EDE4F2` |
| Late night（深夜） | `#263747` | `#304558` | `#FFFFFF` | `#E8EDF1` |

每个 `[data-theme]` 必须定义页面、柔和、卡片、输入、次级、hover、selected、普通边框、强边框、阴影透明度和背景渐变变量。现有 `--color-bg`、`--color-surface` 等组件别名映射到这些变量，不允许组件自行写入主题色。

六个主题的 `--background-gradient` 均为 `none`。组件只能读取主题别名；不得在组件内部再创建平行主题节点或渐变皮肤。

### 共享语义颜色

| Token | 值 | 用途 |
| --- | --- | --- |
| `--color-text` | `#171717` | 主文字 |

| `--color-text-tertiary` | `#5F645F` | 元信息 |
| `--color-action` | `#202020` | 主操作背景 |
| `--color-action-hover` | `#000000` | 主操作悬停 |
| `--color-focus` | 当前主题的 `--color-theme-focus` | 键盘焦点环 |
| `--color-success` | `#477A62` | 条件满足和成功 |
| `--color-warning` | `#8A692F` | 降级和取舍 |
| `--color-error` | `#A84242` | Provider 错误和不可用 |

### 使用规则

- 主操作使用深石墨背景、白色文字；次操作使用白色卡片表面、深色文字和主题强边框。
- 选中状态使用主题次级表面和深石墨边框，不用彩色实心按钮。
- Neutral 依靠边框和极轻表面阴影区分白色卡片；其他主题优先依靠背景差异和边框。
- 绿色只表示成功或真实条件已满足；红色只表示错误；黄色只表示提示和降级。
- 成功、警告、错误必须同时显示文字或图标。
- 正文和关键数据需达到 WCAG 2.2 AA 对比度；禁用文字仍须可辨认。

## 字体 Token

首个版本不下载中文 Web Font，使用系统字体降低加载成本并避免许可与子集问题。

```css
--font-display: "Noto Serif SC", "Source Han Serif SC", "Songti SC", "STSong", serif;
--font-body: "PingFang SC", "Noto Sans SC", "Microsoft YaHei", "Helvetica Neue", Arial, sans-serif;
--font-mono: "IBM Plex Mono", "DM Mono", "SFMono-Regular", "Cascadia Code", Menlo, Consolas, monospace;
```

| Token | 字号/行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| `--text-display` | `40–64px / 1.08` | 600 | 首页主标题，Display |
| `--text-page` | `32–44px / 1.15` | 600 | 页面标题，Display |
| `--text-recommendation` | `30–36px / 1.2` | 600 | 推荐菜名，Display |
| `--text-title` | `22px / 1.35` | 600 | 区块标题，Display |
| `--text-subtitle` | `18px / 1.4` | 600 | 次级标题，Display |
| `--text-body` | `15.5px / 1.65` | 400 | 正文、表单和按钮，Body |
| `--text-label` | `14px / 1.5` | 400–600 | 标签和说明，Body/Mono |
| `--text-caption` | `12px / 1.5` | 400–500 | 状态和元信息，Mono |

首页标题、推荐菜名和结果核心标题使用 Display；长正文使用 Body；步骤、状态、标签、价格、距离和 ETA 使用 Mono，并为数字启用 `font-variant-numeric: tabular-nums`。不加载远程字体，中文正文不得使用等宽字体。

## 布局

### 移动端

```text
┌──────────────────────┐
│ Logo          历史   │
│ 30 秒选好这顿外卖    │
│ 位置                 │
│ 预算  ·  最晚送达    │
│ 当前更在意什么       │
│ [更多偏好]           │
│                      │
│ [给我一个推荐]       │ ← 底部可达
└──────────────────────┘
```

- 关键条件在首屏完成；更多偏好使用折叠区或底部抽屉。
- 主操作在长内容中可使用安全区感知的底部操作栏。
- 推荐首屏应完整显示候选名称、总价、ETA、距离、两条理由和“去下单”。

### 桌面端

```text
┌────────────────────────────────────────────────────┐
│ Logo                                  历史 / 偏好 │
├────────────────────┬───────────────────────────────┤
│ 决策条件 360–420px │ 主推荐                         │
│ 位置、预算、ETA    │ 决策跑道                       │
│ 状态、口味、忌口   │ 理由、取舍、去下单             │
│                    │ 替代候选                       │
└────────────────────┴───────────────────────────────┘
```

- 最大内容宽度 1180px；右侧推荐区占剩余空间。
- 不把移动端长表单原样居中放大。

### 响应式断点

| 范围 | 行为 |
| --- | --- |
| `0–479px` | 紧凑单栏，16px 页面边距 |
| `480–767px` | 宽松单栏，20–24px 页面边距 |
| `768–899px` | 宽松单栏，保留移动端底部操作 |
| `900–1023px` | 单栏，改用卡片内操作，不显示固定底栏 |
| `1024px+` | 400px 条件栏 + 自适应结果栏 |
| `1200px+` | 推荐理由和替代候选可在空间足够时分栏 |

必须在 320px、390px、768px、900px、1024px 和 1440px 验证，不允许横向滚动。

## 组件

### 图片层级与真实性

- 主推荐图片使用 4:3 大图；替代项和多人支持卡使用更小的 4:3 图片，不能与主决定争夺层级。
- 图片只能来自 `./assets/dishes/` 的显式本地白名单。缺失路径、远程 URL、越界路径或非 `dish-inspiration` 的 `kind` 一律回退到中性 `placeholder.svg`；图片加载错误也只执行一次相同回退。
- 仓库包含 12 个为本项目生成、人工检查、1200×900 且移除元数据的 WebP。它们是灵感素材，不代表商家或可下单商品。
- 只有 9 个菜名拥有人工核验的具体映射：照烧鸡腿饭、烧烤烤串、卤味拼盘、卤香干、低脂轻食沙拉、牛油果鸡胸碗、蛋白能量碗、广式云吞汤、红酒烩牛肉。
- 其余 166/175 道菜使用中性占位图。未核验的资产可以被打包但不得按品类默认分配；不能宣称已经实现全部菜品图片覆盖。

### 应用与输入

- `AppHeader`：字标、历史和偏好入口。
- `LocationControl`：定位、手动区域、权限失败和加载状态。
- `BudgetControl`：订单总预算，不使用模糊人均档位。
- `DeliveryTimeControl`：最大 ETA 和必要时的距离上限。
- `PrioritySelector`：快一点、便宜一点、吃得满足、清淡舒服、想吃点新的。
- `PreferenceDisclosure`：折叠口味、忌口和人数。
- `TasteChips` / `ExclusionPicker`：具备可访问的选中状态。
- `ContextSummary`：提交前用一句话汇总条件。

阶段 3.7 当前流程使用更具体的输入契约：人数初始不预选，必填选择完成前下一步禁用；多人使用匿名食客槽位。单选与口味筹码触发局部重绘后，焦点按稳定控件 ID 回到刚操作的控件，不允许落到 `body`。只有前进、返回或结果切换才把焦点移动到新步骤或结果标题。

### 推荐与反馈

- `RecommendationCard`：唯一主推荐；多人模式用带真实英雄菜品的方案摘要承载主决定。
- `DecisionRunway`：预算、ETA、距离、口味状态。
- `ReasonList`：结构化原因，不展示算法内部权重。
- `TradeoffNotice`：明确软条件取舍。
- `AlternativeCard`：单人承载符合条件的菜品替代，多人承载完整方案替代；按钮文案“选择这个方案”必须实际整体提升该方向，不能只显示 toast。
- `EmptyResult`：解释无候选并建议只放宽一个软条件。
- `ModeNotice`：用“菜品参考”标识本地清单结果，并在相邻说明中明确数据来源。
- `PlatformHandoff`：平台跳转、复制关键词和失败后备。
- `ToastRegion`：非关键短反馈，使用 `aria-live="polite"`。
- `Dialog`：权限、清除和重要确认，具备焦点锁定与恢复。

### 统一状态

所有交互组件必须定义：default、hover、focus-visible、pressed/selected、disabled、loading、error 和 unavailable。加载时保持控件尺寸稳定；错误信息靠近控件并说明恢复动作。

## 文案

- 主标题：`人间有味是清欢`
- 流程标题：`循味而选`
- 主按钮：`生成推荐`
- 重新推荐：`换一个`
- 下单：`去下单`
- 返回结果条件：`修改条件`
- 定位失败：`无法获取位置，请选择送达区域`
- 无候选：`暂时没有符合全部条件的菜品`
- 本地清单模式：`菜品参考`，相邻说明为`来自项目内置清单，实际配料请在用餐前确认。`
- 结果分区：`菜品介绍`、`推荐依据`、`食用提示`

避免“提交、落笔定案、择此一席、认命、违抗命运”等文案。标签负责命名，说明负责解释，按钮只描述点击后的动作。

## 动效

- 控件只使用 120–180ms 的背景、边框或颜色变化；不使用漂浮、发光或弹跳。
- 推荐切换不增加编排动画；数据返回后直接更新内容。
- `prefers-reduced-motion: reduce` 下取消加载透明度之外的非必要变化。
- 加载超过 800ms 显示进度文案，超过 8 秒进入可恢复错误状态。

## 可访问性

- 使用 `<main>`、唯一 `<h1>`、顺序正确的标题和真实 `<form>`。
- 每个输入有可见 `<label>` 或等效可访问名称。
- 选择按钮使用 `aria-pressed`，当前步骤/页面使用 `aria-current`。
- 会替换输入子树的选择操作必须通过稳定控件身份恢复逻辑焦点；不能把单选或口味筹码变化后的 `body` 焦点当作预期行为。
- 键盘焦点使用 3px `--color-focus` 环，不移除 outline 后只用颜色代替。
- 对话框使用 `role="dialog"`、`aria-modal="true"`，支持 Escape、焦点锁定和关闭后焦点恢复。
- 错误摘要与字段错误关联；重要状态使用 `aria-live`。
- 触控目标至少 44×44px；支持 200% 缩放和减少动效。
- 发布前以 WCAG 2.2 AA 为验收基线。

## 性能预算

- LCP ≤ 2.5s，CLS ≤ 0.1，INP ≤ 200ms。
- 首屏 JS gzip ≤ 80KB；首屏图片总量 ≤ 250KB。
- 首个版本不依赖远程食物摄影或外部中文字体；项目内图片按显式白名单构建。
- 图标优先使用小型 SVG sprite，不为每个控件内联重复的大段 SVG。

## 设计交付检查

- 提供 320px、390px、768px 和 1440px 截图。
- 覆盖默认、加载、无候选、定位拒绝、灵感模式、实时结果和平台跳转失败。
- 检查键盘顺序、焦点、对比度、200% 缩放和减少动效。
- 对照本文 token 和组件状态审查，不在页面中新增无法解释的颜色、字号、圆角或阴影。
- 复核 12 个 WebP 的本地构建边界、9 个菜名的人工映射和其余 166 道菜的中性占位；视觉相似不能代替语义核验。
