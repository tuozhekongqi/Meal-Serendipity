# 实施计划

## 当前基线（2026-08-17）

- 根目录 `index.html` 是 2,410 行的单文件应用，内联 HTML、CSS、SVG、175 条菜品数据和全部 JavaScript。
- 技术栈为原生 HTML5、CSS3 和 JavaScript，无外部依赖、无 `package.json`、无构建步骤、无自动化测试。
- 状态与历史通过 `localStorage` / `sessionStorage` 保存。
- `一餐之缘_分享版/index.html` 是独立的较小副本，尚无明确同步或发布规则。
- 未发现 GitHub Actions、Netlify、Vercel、Cloudflare、容器或其他部署配置；README 仅建议手动打开或拖放到 Netlify。

## 目标

在不破坏零依赖、离线可用和现有体验的前提下，让推荐逻辑可测试、UI 可维护、发布过程可追踪。每个阶段应独立审查和验收，不一次性重做页面。

## 阶段 0：建立可验证基线

1. 确认根目录版本是否为唯一权威源，以及分享版的生成/发布方式。
2. 记录公开部署地址、目标浏览器和外卖平台跳转约束。
3. 建立覆盖关键流程的手动检查清单和一组固定输入/期望约束样例。
4. 对当前 `index.html` 做静态语法检查并保存移动端、桌面端基线截图。

验收：不改业务行为；团队能重复运行并检查当前版本。

## 阶段 1：推荐逻辑与 UI 解耦

1. 先写测试，覆盖避讳硬过滤、口味/主食匹配、预算边界、天气/场景加分、多人菜单、历史去重和抽签范围。
2. 将菜品数据与标签定义提取为独立数据模块。
3. 将 `banned`、`poolFor`、`scoreFor`、`buildMenu` 和抽签选择提取为不依赖 DOM、`window` 或存储的纯函数。
4. 通过显式输入传入状态、历史和随机源；输出结构化推荐结果与理由。
5. 保留 UI 适配层，负责读取表单、持久化状态和渲染结果。

验收：固定输入得到可重复结果；所有硬过滤测试通过；现有用户流程和离线能力保持不变。

## 阶段 2：可维护的页面边界

1. 在不重做视觉的前提下，按封面、表单、模式、结果和下单页整理渲染与事件绑定。
2. 统一设计令牌、按钮/选择项/卡片状态和反馈方式。
3. 补齐减少动效、键盘焦点、表单标签和错误可访问性。
4. 明确分享版是删除、归档、手工维护还是由脚本生成。

验收：320px 至桌面无横向溢出；键盘主流程可用；控制台无新增错误；页面视觉没有未经批准的整体重做。

## 阶段 3：自动化与部署

1. 根据阶段 1 的模块形式选择最小测试工具；不要先引入完整框架。
2. 添加静态检查、核心逻辑测试和关键浏览器流程测试。
3. 选择并记录部署平台，增加最小部署配置和预览环境。
4. 为 Pull Request 运行检查；失败时禁止合并。

验收：新分支可生成预览；核心测试自动运行；发布来源和回滚方式清晰。

## 每次变更的检查门槛

- 修改前：阅读规则与相关源码，记录基线，写明范围、风险、验证和回滚。
- 修改后：运行静态服务，检查控制台，走通快速/完整/多人/避讳/三案/摇签/下单/恢复流程。
- 视口：至少检查 320px、常见手机宽度和桌面宽度。
- 推荐逻辑：运行确定性测试并确认避讳不会被任何回退绕过。
- Git：检查 diff，只提交计划内文件；从非 `main` 分支发起 Pull Request。
